# Class Notes(Cloud)

## 2026-06-01 (day 13)

### 강의

1. Spring Boot
    - Spring 기반 애플리케이션을 빠르게 개발하도록 도와주는 프레임워크.
    - Auto-Configuration
        - 클래스패스와 설정 정보를 기준으로 필요한 빈 자동 등록.
        - @SpringBootApplication 하나로 자동설정, 컴포넌트 스캔, 설정 클래스 활성화.
    - Starter Dependencies
        - 기능별 의존성 묶음으로 버전 충돌 감소 및 초기 구성 단순화.
        - 웹 스타터 사용 시 내장 Tomcat 기반 서버 함께 구성 가능.
    - (dependency)
        - p6spy: 실행 SQL을 로그로 확인해 쿼리 동작 검증에 사용.

2. ORM/JPA 기초
    - ORM
        - 객체와 테이블을 매핑해 SQL 중심 개발을 객체 중심으로 바꾸는 기술.
    - JPA(Java Persistence API)
        - 자바 ORM 표준 명세(인터페이스)이며 구현체로 Hibernate 등 사용.
    - Hibernate
        - JPA 구현체로 SQL 생성/실행, 캐시, 지연 로딩 등 영속성 기능 실제 수행.
    - Annotation
        - 엔티티, 컬럼, 관계 같은 매핑 정보를 코드에 선언적으로 표현.
    - DTO
        - 계층 간 데이터 전달 전용 객체로, 보통 비즈니스 로직 없이 값만 보관.

3. 엔티티 설계
    - Entity
        - 테이블과 1:1로 매핑되는 도메인 객체.
        - 프록시 생성을 위해 기본 생성자 필요, final class 사용 지양.

4. 기본 키 생성 전략
    - IDENTITY
        - DB의 auto increment 사용, INSERT 시점에 PK 생성.
    - SEQUENCE
        - DB 시퀀스 객체에서 다음 키 값 선조회 후 엔티티에 할당.
    - TABLE
        - 키 생성 전용 테이블로 시퀀스를 흉내 내는 방식, 범용성은 높지만 성능 비용 큼.
    - AUTO
        - 사용 DB 방언에 맞춰 JPA 구현체가 적절한 키 전략 자동 선택.

5. 컬럼 매핑
    - @Column
        - 컬럼명, 길이, nullable, unique 등 컬럼 속성 지정.
    - @Enumerated
        - enum 값을 DB에 저장할 때 STRING 또는 ORDINAL 방식 선택.
    - @Transient
        - DB에 저장하지 않을 필드를 엔티티 내부 계산/임시값 용도로 선언.

6. 영속성 컨텍스트
    - EntityManager
        - 영속성 컨텍스트에 엔티티를 저장/조회/수정/삭제하는 핵심 API.
    - 1차 캐시
        - 같은 트랜잭션에서 동일 PK 조회 시 DB 대신 캐시 재사용.
    - 쓰기 지연
        - INSERT/UPDATE SQL 즉시 실행 없이 트랜잭션 커밋 시점에 모아 반영.
    - 변경 감지(Dirty Checking)
        - 영속 상태 엔티티 변경을 스냅샷 비교로 감지해 UPDATE SQL 자동 생성.
    - 엔티티 생명주기
        - 비영속: 영속성 컨텍스트에 관리되지 않는 신규 객체 상태.
        - 영속: EntityManager가 관리하며 변경 감지 대상이 되는 상태.
        - 준영속: detach로 관리 대상에서 분리된 상태.
        - 삭제: remove 호출로 삭제 예정이 된 상태.
    - 트랜잭션
        - 커밋 시 flush 발생, 지연된 SQL DB 반영.

7. 연관관계/프록시/지연 로딩
    - 연관관계 매핑
        - 객체 참조 관계를 외래 키 기반의 테이블 관계로 연결해 표현.
    - 프록시
        - 실제 엔티티 대신 참조되는 대리 객체, 초기 조회 비용 절감에 사용.
    - 지연 로딩(LAZY)
        - 연관 엔티티가 실제로 필요한 시점에 조회 쿼리 실행.
    - 즉시 로딩(EAGER)
        - 연관 엔티티 즉시 함께 조회, N+1 문제 주의 필요.

8. 키워드 정리
    - ORM
        - 객체와 테이블의 매핑을 통해 SQL 중심 개발을 객체 중심으로 바꾸는 기술
        - 사용 이유: 반복적인 CRUD SQL 작성 부담을 줄이고 도메인 중심으로 생산성 높게 개발하기 위한 사용.
    - JPA
        - 자바에서 ORM을 사용하기 위한 표준 인터페이스(명세)이며 구현체로 Hibernate 등을 사용
        - 사용 이유: 구현체에 종속되지 않는 일관된 방식으로 영속성 로직을 작성해 유지보수성과 이식성 향상을 위한 사용.
    - Entity
        - 테이블과 1:1로 매핑되는 도메인 객체
        - 사용 이유: 비즈니스 데이터와 행위를 객체로 모델링해 DB 데이터와 애플리케이션 로직의 자연스러운 연결을 위한 사용.
    - 영속성 컨텍스트
        - 엔티티를 저장·관리하며 1차 캐시, 변경 감지, 쓰기 지연을 제공하는 JPA의 핵심 관리 영역
        - 사용 이유: 트랜잭션 내 데이터 일관성 유지와 성능 최적화(캐시, 배치성 쓰기)를 위한 사용.
    - 연관관계 매핑
        - 객체 간 관계를 테이블 관계와 연결해 표현하는 설정
        - 사용 이유: 조인 관계를 객체 참조로 다뤄 도메인 모델의 직관적 표현과 탐색 코드 단순화를 위한 사용.
    - Proxy
        - 실제 엔티티 조회를 지연시키기 위해 생성되는 대리 객체(접근 시점에 실제 데이터를 로딩)
        - 사용 이유: 당장 필요 없는 연관 데이터 지연 조회로 불필요한 쿼리 감소 및 초기 조회 성능 개선을 위한 사용.
