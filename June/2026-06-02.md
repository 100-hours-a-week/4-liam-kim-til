# Class Notes(Cloud)

## 2026-06-02 (day 14)

### 강의

1. JPA
    - 기본 값 타입
        - @Entity
        - 단일 값으로만 의미를 가지는 데이터 (int, String 같은 원시/래퍼/문자열)
        - 생명주기가 엔티티에 완전히 종속됨 (별도 식별자 없음)
        - 값이 바뀌면 "교체" 개념으로 다루는 게 안전함 (공유해서 변경하면 부작용 가능)
    - 임베디드 타입
        - @Embeddable
        - 2개 이상의 값을 하나의 객체로 묶어 엔티티에 포함시켜 사용하는 타입
        - @Embedded로 엔티티 내부에 포함해서 사용
        - 테이블을 분리하지 않고, "같은 테이블 컬럼들"로 펼쳐서 매핑됨 (별도 PK/FK 없음)
        - 같은 임베디드 타입을 여러 번 쓰면 @AttributeOverrides로 컬럼명 충돌 해결
    - 컬렉션 타입
        - @CollectionTable
        - 값 타입 컬렉션(List<String>, Set<Address> 등) 매핑할 때 사용
        - 엔티티와는 별도의 컬렉션 테이블이 생성되고, 소유 엔티티 PK를 FK로 가짐
        - 값 타입 컬렉션은 원소 단위 추적이 약해서 변경 시 delete + insert가 자주 발생
        - 대량 수정/부분 수정이 많으면 값 타입 컬렉션보다 엔티티 연관관계로 푸는 게 유리
2. JPQL
    - N+1
        - 조회 1번 + 연관 엔티티 조회 N번이 추가로 발생하는 문제
        - LAZY에서 연관 객체 접근 시점에 반복 쿼리가 터지기 쉬움
        - 해결: fetch join, @EntityGraph, 배치 사이즈 설정(@BatchSize) 등
        - ToOne은 fetch join으로 효과가 크고, ToMany는 페이징/중복 이슈를 같이 고려
    - Projection
        - 엔티티 전체가 아니라 필요한 필드만 조회하는 방식
        - Scalar Projection: Object[]/Tuple로 단일 컬럼들만 조회
        - DTO Projection: new 패키지.DTO(...) 형태로 바로 DTO 생성
        - Entity Projection: 엔티티 자체를 조회 (변경 감지 가능)
        - 성능 최적화 관점에서 "화면에 필요한 데이터만" 가져올 때 특히 유용
        - 단, 복잡한 화면은 DTO 전용 쿼리와 엔티티 조회 쿼리를 분리하는 게 유지보수에 좋음
3. Spring Data JPA
    - 반복적인 CRUD 코드 없이 interface 만 작성하면 됨.
    - 이게 내가 생각하는 DRF 같은건가??
    - Query Method
        - 메서드 이름으로 쿼리를 자동 생성 (findByEmailAndStatus 같은 패턴)
        - 단순 조건은 빠르게 개발 가능, 너무 길어지면 가독성이 급격히 떨어짐
    - @Query
        - 복잡한 JPQL/Native SQL을 직접 명시할 때 사용
        - 조회 전용 최적화 쿼리 작성에 유리하고, 의도를 코드에 명확히 남길 수 있음
    - @EntityGraph
        - 연관 엔티티를 즉시 로딩(fetch)해서 N+1을 줄이는 선언적 방법
        - fetch join을 메서드 단위로 깔끔하게 적용하는 느낌
    - Pageable
        - 페이징/정렬 정보를 파라미터로 받아 자동으로 limit/offset 처리
        - 반환 타입 Page, Slice 차이 이해 필요 (전체 count 쿼리 유무)
4. Query DSL
    - BooleanBuilder
        - 동적 쿼리 작성에 특화된 타입 세이프 쿼리 도구
        - 문자열 JPQL보다 컴파일 타임 검증이 가능해서 리팩터링에 강함
        - 조건이 많을 때 BooleanBuilder로 where 절을 조립해서 가독성 있게 관리 가능
        - 복잡한 검색 API(필터 다수, 선택 조건 다수)에서 특히 장점이 큼
