# Class Notes(Cloud)

## 2026-05-19 (day 5)

### 강의

1. 스프링 MVC
    - 한 줄 요약
        - 모든 요청을 DispatcherServlet이 받아서, 적절한 컨트롤러로 전달하고, 결과를 ViewResolver를 통해 응답으로 만든다.
    - Servlet
        - 자바 기반 웹 애플리케이션에서 HTTP 요청/응답을 처리하는 서버 측 컴포넌트
        - 스프링 MVC는 서블릿 기술 위에서 동작함
    - DispatcherServlet(프론트 컨트롤러)
        - 클라이언트의 모든 요청을 가장 먼저 받는 진입점
        - 요청 URL/메서드에 맞는 핸들러(컨트롤러 메서드)를 찾고 실행을 위임
        - 공통 처리(예외 처리, 인터셉터, 데이터 바인딩 등)를 한곳에서 관리
    - HandlerMapping
        - 어떤 요청을 어떤 컨트롤러 메서드가 처리할지 매핑 정보를 제공
        - 예: `GET /books` -> `BookController.findAll()`
    - ViewResolver
        - 컨트롤러가 반환한 논리적 뷰 이름을 실제 뷰 경로로 변환
        - 예: `home` -> `/templates/home.html` -> 그냥 템플릿 엔진 경로버젼??...
    - 기본 요청 처리 흐름
        - 클라이언트 요청
        - DispatcherServlet 수신
        - HandlerMapping으로 핸들러 조회
        - 컨트롤러 실행
        - ViewResolver로 뷰 결정(또는 REST라면 JSON으로 바로 응답)
        - 응답 반환
2. 레이어드 아키텍처
    - 관심사를 분리해 유지보수성, 테스트 용이성, 확장성을 높임
    - 계층
        - Controller
            - HTTP 요청/응답 처리, 입력값 검증, DTO 변환
        - Service
            - 비즈니스 로직 처리, 트랜잭션 경계 관리
        - Repository(DAO)
            - DB 접근 및 영속성 처리
        - Domain(Entity)
            - 핵심 비즈니스 데이터와 규칙 표현
    - 의존 방향
        - Controller -> Service -> Repository
        - 하위 계층은 상위 계층을 알지 않도록 설계
    - 역할 분리가 명확해 코드 이해가 쉬움
    - 단위 테스트 작성이 쉬움(계층별 Mock 처리 가능)
    - 변경 영향 범위를 줄일 수 있음
3. HTTPS
    - HTTPS = HTTP + TLS(암호화, 무결성, 서버 인증)
    - 암호화/복호화
        - 암호화: 평문을 읽을 수 없는 형태로 변환
        - 복호화: 암호문을 원래 데이터로 복원
    - 대칭키 암호화
        - 하나의 동일한 키로 암호화/복호화
        - 장점: 매우 빠름(대용량 데이터 전송에 적합)
        - 단점: 키를 안전하게 공유하기 어려움
    - 비대칭키(공개키) 암호화
        - 공개키/개인키 한 쌍 사용
        - 공개키로 암호화한 데이터는 개인키로만 복호화 가능
        - 장점: 키 교환 문제를 완화
        - 단점: 연산량이 커서 느림
    - 전자서명
        - 서명 생성: 개인키로 서명
        - 서명 검증: 공개키로 검증
        - 목적: 위변조 방지(무결성) + 서명 주체 확인(인증)
    - HTTPS 동작 흐름(개념)
        - 클라이언트가 서버에 접속
        - 서버가 인증서(공개키 포함)를 전달
        - 클라이언트가 인증서 신뢰 여부 확인(CA 체인 검증)
        - 클라이언트/서버가 대칭키(세션 키)를 안전하게 합의
            - 이때 비대칭키 방식이 사용됨
        - 실제 HTTP 데이터는 대칭키로 암호화해서 송수신
    - 인증서와 CA
        - 인증서: 서버 신원을 증명하는 디지털 문서(서버 공개키 포함)
        - CA(인증기관): 인증서에 전자서명하여 신뢰를 보증
        - 브라우저/OS는 신뢰할 수 있는 루트 CA 목록을 보유
    - 확인 문제 정리
        - 대칭키와 비대칭키의 차이점?
            - 대칭키: 빠르지만 키 공유가 어려움
            - 비대칭키: 키 공유가 상대적으로 안전하지만 느림
        - 비대칭키의 처리속도가 느린 이유?
            - 큰 정수 기반의 복잡한 수학 연산(모듈러 지수 연산 등)을 사용하기 때문
        - HTTPS에서 실제 데이터 전송 시 사용하는 키는?
            - 대칭키(세션 키)
        - 전자서명 시 사용하는 키는?
            - 서명 생성: 개인키
            - 서명 검증: 공개키
            - 인증서의 서명은 CA의 개인키로 생성됨
