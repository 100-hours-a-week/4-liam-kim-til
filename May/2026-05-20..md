# Class Notes(Cloud)

## 2026-05-20 (day 6)

### 강의

1. OOP
    - Procedural (절차지향)
    - Object-Oriented (객체지향)
    - 객체지향적 설계
    - 책임에 따른 설계가 필요함
    - Spring Boot
        - Controller
            - 요청 흐름
        - Service
            - 비즈니스 로직
        - Repository
            - 데이터 접근 책임
2. SOLID
    - SRP (단일 책임 원칙)
        - 클래스를 수저앟는 이유는 한가지다?
    - OCP (개방 폐쇄 원칙)
        - 확장은 열어두고 기존 코드 수정은 닫아라
    - LSP (리스코프 치환 원칙)
        - 자식 클래스는 언제나 부모 클래스를 대체할 수 있어야한다?
    - ISP (인터페이스 분리 법칙)
        - 내가 안쓰는 거대한 인터페이스보다 쪼개진 인터페이스를 쓰자
    - DIP (의존관계 역전)
        - 구체적인 것에 의존하지말고 추상적인 것에 의존해라
3. JVM
    - 전체 구조
        - Class Loader Subsystem(클래스 로더 서브시스템)
        - Runtime Data Areas(런타임 데이터 영역)
        - Execution Engine(실행 엔진)
        - JNI(Java Native Interface)
        - Native Libraries(C/C++ 같은 네이티브 라이브러리)
        - 즉, JVM은 "클래스 로더 + 메모리 영역 + 실행엔진"만이 아니라 JNI/네이티브 연동까지 포함
    - 클래스 로더
        - loading
        - linking
            - verifying
            - preparing
            - resolving
        - initialization
        - 역할: `.class` 바이트코드를 읽어 JVM 메모리에 적재하고, 링크/초기화 수행
        - 로더 계층: Bootstrap -> Platform(Extension) -> Application
    - 실행엔진
        - 인터프리터: 바이트코드를 한 줄씩 해석/실행
        - JIT 컴파일러: 자주 실행되는 핫스팟 코드를 네이티브 코드로 컴파일
        - GC(가비지 컬렉터): 사용하지 않는 객체 메모리 회수
        - 코드 캐시(Code Cache): JIT가 만든 네이티브 코드를 저장해 재사용
    - 런타임 데이터 영역
        - Method Area(메서드 영역, HotSpot에서는 Metaspace): 클래스 메타데이터, static 변수, 런타임 상수풀
        - Heap: 객체/배열 저장, GC 대상
        - Stack(스레드별): 메서드 호출 프레임, 지역변수, operand stack
        - PC Register(스레드별): 현재 실행 중인 JVM 명령어 주소
        - Native Method Stack: JNI 등 네이티브 메서드 실행용 스택
    - 실행 흐름 요약
        - Java 소스(.java) -> 컴파일러(javac) -> 바이트코드(.class)
        - 클래스 로더가 로드/링크/초기화
        - 실행엔진(인터프리터 + JIT)이 실행
        - 필요 시 JNI를 통해 네이티브 라이브러리 호출
    - 퀴즈
        - JVM이 하는 일이 무엇인가
            - 바이트코드 실행
            - 메모리 관리
            - 플랫폼 독립 실행 환경 제공(Write Once, Run Anywhere)
        - 클래스 로더가 하는 일
            - 클래스 바이트코드를 로드하고 링크(검증/준비/해결) 후 초기화
        - 실행엔진은 어떤 일을 하나요?
            - 인터프리터로 실행하고, 핫스팟은 JIT로 네이티브 코드로 컴파일해 성능 최적화
        - JIT 은 언제 어떻게 동작하나요
            - 메서드/루프가 충분히 많이 실행되어 핫스팟으로 판단되면 네이티브 코드로 컴파일
            - 이후 동일 코드는 컴파일된 네이티브 코드를 재사용해 더 빠르게 실행
            - 모든 코드를 미리 컴파일하는 것이 아니라 "자주 실행되는 부분" 위주로 최적화
