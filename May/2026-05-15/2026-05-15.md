    - 쓰레드
        - 하나의 프로그램(프로세스) 내에서 동시에 실행될 수 있는 독립적인 실행 흐름 단위
        - 빠르게 하기 위함은 아니고 병렬적으로 실행시키기 위함.(백그라운드 작업, 동시처리 -> 결과적으로 빨라 질 수 있음.)
        - 임계 영역에 대해
            - C에서는 ++, += 이 어셈블리어로 INC랑 ADD로 해석되니까 해당 영역에 ++ 은 문제없이 동작할거라고 생각했는데 INC 자체가 멀티코어 환경에서는 제대로 동작하지 않을 수 있다라고 함.
    - Runnable
        - 새로운 실행 흐름 작업의 정의서
        - 쓰레드를 상속받으면 상속은 1개만 가능하니 interface 방식의 쓰레드 작업의 생성방식
        - Task 와 비슷하고 쓰래드 생성 후 쓰레드에 작업 실행을 배정해줘야함.
    - ExecutorService
        - 쓰레드는 일반적으로 직접 생성하지 않는다.
            - (쓰레드 풀인가?)
                - with ~ as ~ 문 + 쓰레드 풀과 같은 의미인듯?
            - 생성비용이 높다.
            - 리소스 고갈 문제
        - Task Submitters -> Blocking Queues -> Tread Pool 로 구성되어있음
        - newFixedThreadPool(int nThreads)
        - newCachedThreadPool()
        - newSingleThreadExecutor()
        - newScheduledThreadPool(int corePoolSize)
    - Synchronized
        - 여러 쓰레드가 동시에 공유 자원에 접근하지 못하도록 일시적으로 해당 자원에 대한 접근을 제한하는 동기화 코드
        - 쓰레드 -> 일반적으로 스택, 다만 힙 영역 조회시 문제가 생길 수 있음.
        - GIL?
        - 대기하고 있는 쓰레드가 무한히 대기할 수 있음.
    - Lock
        - Python 에서는 알아서 해주던?(경우에 따라 다르긴 하지만) 작업을 수동으로 해야하는 만큼 작업할때에 주의가 필요함.
