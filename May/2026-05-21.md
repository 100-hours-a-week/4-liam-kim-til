# Class Notes(Cloud)

## 2026-05-21 (day 7)

### 강의

1. 상태와 연결
    - Stateful
        - 이전 요청의 상태를 서버가 기억하고 다음 요청 처리에 사용
        - 사용자별 문맥 유지가 쉬움 (예: 로그인 세션, 장바구니)
        - 서버 메모리/확장성 관리가 중요해짐
    - Stateless
        - 각 요청을 독립적으로 처리, 이전 요청 상태를 서버가 저장하지 않음
        - 확장성과 장애 대응에 유리함
        - 필요한 정보는 매 요청마다 함께 전달해야 함 (예: 토큰)
    - Connection oriented
        - 연결을 먼저 맺고 신뢰성 있게 데이터를 주고받는 방식 (예: TCP)
        - 순서 보장/재전송/흐름제어 지원
    - Connectionless
        - 연결 설정 없이 데이터그램 단위로 전송하는 방식 (예: UDP)
        - 지연이 적고 빠르지만 손실/순서 보장은 약함
2. 인증
    - 쿠키
        - 브라우저(클라이언트)에 저장되는 작은 데이터
        - 서버는 쿠키 값을 읽어 사용자 식별에 활용
        - 민감정보 직접 저장은 지양, 보안 옵션(HttpOnly, Secure, SameSite) 중요
    - 세션
        - 사용자 상태 정보를 서버에 저장하고, 클라이언트는 세션 ID만 전달
        - 쿠키보다 민감정보 노출 위험이 낮지만 서버 저장소 비용이 듦
        - 만료시간/세션 고정 공격 대응 등 운영 정책이 중요
3. 프레임워크와 라이브러리
    - 프레임워크
        - 기본적인 구조
        - 기본적인 규칙
        - 기본적인 기능
        - 일관성
        - 제어의 역전(IoC): 프레임워크가 흐름을 주도하고 개발자가 코드를 끼워 넣음
        - 팀 단위 개발에서 코드 스타일과 아키텍처 통일에 유리
    - 라이브러리
        - 빠른 개발
        - 높은 완성도
        - 전문성
        - 필요한 기능만 선택적으로 가져와 사용 가능
        - 애플리케이션 흐름은 개발자가 직접 제어
        - 조합이 자유로운 대신 구조 일관성은 스스로 관리해야 함
4. API(Application Programming Interface)
    - 서로 다른 소프트웨어가 정해진 규칙으로 통신할 수 있게 만든 접점
    - 요청/응답 형식이 명확하다 (예: URL, HTTP Method, JSON)
    - 내부 구현을 몰라도 약속된 방식으로 기능을 사용할 수 있다
    - 재사용성과 확장성이 좋아 프론트엔드-백엔드, 서비스-서비스 연동에 유리하다
    - 문서화(명세)가 중요하다 (예: 어떤 값을 보내고 어떤 값을 받는지)
5. 페이징
    - 한정된 용량에서 데이터를 한번에 처리할 수 있는 적당한 크기로 나눠서 처리하는 것
    - 페이징은 보통 DB 조회 성능 관점(데이터를 나눠 가져오기)에서 많이 쓰는 표현
    - 페이지네이션은 사용자 화면 관점(페이지 번호/다음/이전)까지 포함한 표현
    - 즉, 실무에서는 비슷하게 쓰지만 문맥상 페이지네이션이 더 넓은 개념으로 볼 수 있음
