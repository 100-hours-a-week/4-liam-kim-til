# Class Notes(Cloud)

## 2026-05-28 (day 11)

### 강의

1. NoSQL
    - In memory Store
        - 데이터를 메모리(RAM)에 저장해 매우 빠른 읽기/쓰기 성능 제공
        - 재시작/장애 시 데이터 유실 방지를 위해 스냅샷(AOF/RDB) 같은 영속화 전략 필요
        - 예: Redis, Memcached
    - Key-Value Store
        - key 하나에 value 하나를 매핑하는 단순 구조로 대규모 트래픽 처리에 유리
        - 세션, 캐시, 토큰 저장처럼 빠른 조회가 중요한 시나리오에 적합
        - 예: Redis, DynamoDB, Riak
        - In memory와 Key-Value는 서로 다른 분류 축이며, Redis처럼 둘 다에 해당할 수 있음
    - Document Store
        - JSON/BSON 문서 단위 저장으로 스키마 변경이 비교적 유연
        - 중첩 구조 데이터 표현과 문서 기반 조회에 강점 (MongoDB)
    - Column-Oriented Store
        - 컬럼 패밀리 기반 저장 구조로 대용량 분산 저장과 쓰기 확장성에 강함
        - 로그/시계열/분석성 워크로드 처리에 적합 (Cassandra, HBase)
    - Graph Store
        - 노드(Node)와 엣지(Edge)로 관계를 저장해 관계 탐색 성능이 우수
        - 추천 시스템, 소셜 네트워크, 경로 탐색 같은 관계 중심 도메인에 적합
2. 데이터베이스 확장
    - Partitioning
        - Vertical
            - 테이블의 컬럼을 기준으로 분리해 I/O 부하를 분산
            - 자주 접근하는 컬럼과 그렇지 않은 컬럼을 분리해 성능 최적화
        - Horizontal
            - 같은 스키마를 행(row) 기준으로 여러 DB 샤드에 분산 저장
            - 데이터 증가에 따라 노드 추가로 확장(scale-out) 가능
    - Replication
        - Master/Slave
            - Primary(=Master)는 쓰기, Replica(=Slave)는 읽기를 담당(읽기/쓰기 분리)
            - 복제 지연(replication lag)으로 읽기 일관성 이슈가 발생할 수 있음
3. Server Cache
    - Local Cache
        - 애플리케이션 인스턴스 내부 메모리에 저장해 지연 시간이 가장 짧음
        - 인스턴스별 데이터가 달라질 수 있어 분산 환경에서 캐시 일관성 관리 필요
    - Global Cache
        - 여러 인스턴스가 공유하는 외부 캐시 계층으로 캐시 일관성 유지에 유리
        - 네트워크 홉이 추가되어 Local Cache보다 지연이 커질 수 있음
        - DB
            - DB 버퍼 캐시/쿼리 캐시를 통해 디스크 접근을 줄여 조회 성능 개선
        - Storage
            - 객체 스토리지/파일 스토리지 앞단 캐시로 정적 자원 접근 속도 향상
        - CDN
            - 사용자와 가까운 엣지 서버에 콘텐츠를 캐시해 전송 지연 및 원본 부하 감소
        - Proxy
            - 리버스 프록시(Nginx 등)에서 응답 캐시를 수행해 백엔드 요청 수 절감
