### 강의

1. Git & GitHub 개념
    - 버젼 + 관리 + 시스템
    - 분산 버젼 관리 시스템
        - 프로젝트의 전체 히스토리와 버전 관리 정보를 각 사용자의 로컬 시스템에 복제하여, 네트워크에 의존하지 않고도 버전 관리를 수행할 수 있도록 하는 시스템
2. 명령어
    - git add
        - 파일 추가
    - git status
        - 현재 브랜치 상태와 변경 파일(추적/미추적, 스테이징 여부)을 확인
    - git diff
        - 파일의 변경사항 비교
    - git rebase
        - 커밋의 기준(base)을 다른 브랜치로 옮김
    - git merge
        - 브랜치를 한 곳으로 합침
    - git bisect
        - 이진 탐색 방식으로 문제를 일으킨 커밋을 빠르게 찾아내는 디버깅 함
    - git restore
        - 작업 디렉터리 또는 스테이징 영역의 파일을 특정 상태로 되돌림
    - git revert
        - reset 과 다르게 기록이 남는것이 특징
        - 협업 중인 브랜치에서는 reset보다 revert를 권장
    - git reset
        - 커밋을 지정한 지점으로 이동시키는 명령어
    - .gitignore
        - git 사용시 제외할 파일, 폴더, 패턴 모음
3. 병합(merge)방식
    - 3-way merge
        - 병합할 두 브랜치(branch)와 공통의 조상(ancestor) 커밋을 이용하여 병합하는 방식입니다. 이 방식은 가장 일반적인 병합 방식으로, 자동으로 처리됩니다
    - fast-forward merge
        - 새로운 브랜치(branch)를 만들고, 해당 브랜치에서 변경사항을 추가(commit)한 후에, 메인 브랜치(main branch)에 그대로 적용하는 병합 방법입니다. 
    - squash and merge
        - 새 브랜치의 커밋기록을 으깨서 메인브랜치에 하나로 넣는다.
4. GenAI
    - 프롬프트 엔지니어링
        - 맥락 제시
        - 목적 제시
        - 형식 제시
        - 예시 제시
    - 사용 기법
        - Single Turn
            - 대화 형식이 아닌 한 번의 질문을 통해 답변을 받는 방식
        - Multi Turn
            - 여러 번의 대화를 통해 최종 답변을 받는 방식
        - Few Shot
            - 약간의 정보를 제공하여 답변의 질을 올리는 기법
        - 역할 부여
            - 프롬프트를 작성할 때 내가 질문하는 분야에서 답변을 잘 할 수 있는 역할을 선정하여 ChatGPT에게 질문과 함께 역할을 지정해주는 기법
        - 마크다운
            - 일반 텍스트 기반의 경량 마크업 언어를 사용하여 프롬프트를 제작하는 기법
        - 후카츠 프롬프트
            - 지시문, 제약조건, 입력문, 출력조건 이라는 4가지 조건을 사용해 질문 작성
        - Co-star
            - AI에게 명확하고 통제 가능한 출력을 유도하기 위해 사용하는 6요소 프레임워크
        - 생각의 사슬 (Chain of Thought)
            - 여러 단계를 거쳐 차근차근 논리적으로 사고할 수 있도록 유도하는 프롬프트 설계 기법
        - 생각의 나무 (Tree of Thought)
            - 문제를 다각도로 나누고, 각 관점에서 독립된 사고 흐름을 전개시킨 뒤, 이를 비교·평가하여 최선의 결론을 선택하도록 가이드함
